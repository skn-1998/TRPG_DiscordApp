# Source To Rule Map

This map covers production behavior only.

| ID | Production rule | Classification | Evidence and limits |
| --- | --- | --- | --- |
| `BC-SOURCE-AUTHORITY` | Current domain evidence controls the case; MinoDriven controls primary design intent; Evans refines formal mechanics | External plus local precedence | `SRC-MINO-BC-2022`, `SRC-MINO-PURPOSE-ARCH`, `SRC-EVANS-DDD-REFERENCE`; none supplies facts about the user's domain |
| `BC-CLOSED-EVIDENCE` | Use supplied or user-designated evidence and preserve unreproduced artifacts and contradictions; do not import unrelated prior runs or workspaces | Local anti-invention rule | `LOCAL-HIERARCHY-BRIEF`; external sources do not define filesystem scope |
| `BC-COMMON-CONTRACT` | Reconstruct Actor, Purpose, Context, Constraints, and Evidence once; keep workflow actions outside domain Purpose and Evidence | External purpose framing plus user-required local contract | `SRC-MINO-PURPOSE-ARCH`; the five-field schema is local |
| `BC-METHOD-BOUNDARY` | Perform boundary discovery only; hand downstream domain methods to `domain-design`; exclude subdomain, relationship-pattern, code, approval, persistence, and implementation work | External pattern distinctions plus local hierarchy | `SRC-EVANS-DDD-REFERENCE`, `LOCAL-HIERARCHY-BRIEF` |
| `BC-CURRENT-TERRAIN` | Map models already in play before proposing transformation; do not inflate uses of one model into distinct current models | External DDD rule plus conservative evidence handling | `SRC-EVANS-DDD-REFERENCE`, printed p.29 / physical PDF p.36 |
| `BC-PURPOSE-MODEL` | Treat a Bounded Context as the applicability range of a purpose-specific model; require evidence before calling a purpose established | Primary MinoDriven intent | `SRC-MINO-BC-2022`, slides 20-21 and 28; `SRC-MINO-PURPOSE-ARCH`, slides 40-47 |
| `BC-SIGNAL-AXES` | Compare large-grained purpose, closed process cycle, strongly related concepts, invariants, meaning, and applicability | MinoDriven perspectives plus DDD mechanics | `SRC-MINO-BC-2022`, slides 30-33; `SRC-EVANS-DDD-REFERENCE`, printed pp.2-4 |
| `BC-EXPLICIT-APPLICABILITY` | State where each model is valid, invalid, or unknown | External DDD rule | `SRC-EVANS-DDD-REFERENCE`, printed p.2 |
| `BC-CANDIDATE-STATES` | Separate supported candidates, hypotheses, insufficient supplied proposals, conflicts, and evidence-based rejection | Local conservative operationalization | Sources support evidence-based boundaries but not these exact state names |
| `BC-NO-SURFACE-MERGE` | Same names or similar logic never prove that models should be merged | Primary MinoDriven rule | `SRC-MINO-BC-2022`, slides 26-28 |
| `BC-TOPOLOGY-CORROBORATION` | Teams, applications, codebases, schemas, services, and deployments are manifestations or corroboration, not sole boundary proof | Evans mechanics constrained by MinoDriven purpose intent | `SRC-EVANS-DDD-REFERENCE`, printed p.2; `SRC-MINO-BC-2022`, slides 28 and 30-33 |
| `BC-ALTERNATIVES` | Compare a proposed split with keep-together and supplied alternatives before calling it supported | Local anti-overclaim control | External sources support comparison factors, not this exact procedure |
| `BC-MODEL-CONTACTS` | Keep current contacts between evidenced models separate from possible candidate interactions; do not select a relationship pattern | External DDD mechanics plus local evidence scope | `SRC-EVANS-DDD-REFERENCE`, printed p.29 |
| `BC-AUTHORITY-UNCERTAINTY` | Separate evidence source, owner, decision authority, author, and reviewer; preserve unknowns and ask neutral questions | Local governance informed by AI restraint | `SRC-MINO-DDD-AI-2025`, slides 24-29; it does not define these exact roles |
| `BC-READINESS-REVIEW` | Separate report completion from downstream readiness; never self-approve baseline, persistence, or implementation | User-required review design plus local governance | `LOCAL-HIERARCHY-BRIEF` |
| `BC-OUTPUT-CONTRACT` | Return concise evidence-linked conclusions, uncertainty, readiness, and handoffs without fixed prose serialization | User-required input/output/completion contract plus Skill authoring guidance | `SRC-OPENAI-SKILL-CREATOR`; it supports concise procedural guidance, not a specific report grammar |
