# Source To Rule Map

This map covers production routing behavior only.

| ID | Production rule | Classification | Evidence and limits |
| --- | --- | --- | --- |
| `DC-PARENT-ONLY` | Select, order, and contract foundational work without performing or fabricating child methods | User-required hierarchy plus Skill modularity | MinoDriven Modifius modular prompts; Agent Skills coherent-unit guidance; neither defines this exact parent |
| `DC-COMMON-CONTRACT` | Normalize Actor, Purpose, Context, Constraints, and Evidence; preserve material unknowns; do not treat a request to discover stakeholder Purpose as evidence of that Purpose | MinoDriven intent plus user-required local contract | MinoDriven purpose/context sources support Purpose and Context; the five-field schema and conservative evidence rule are local |
| `DC-DIRECT` | Use one exact child directly for one requested method; use this parent for composition, ambiguity, missing declared capability, or returned-result coordination | User-required hierarchy plus Skill modularity | Agent Skills coherent-unit and composition guidance |
| `DC-PGM` | Route Purpose, Goal conditions, Constraints, and Means separation to `purpose-goal-means` | Primary MinoDriven design intent | Purpose-driven architecture deck; formal decision-state mechanics remain child-owned |
| `DC-QUALITY` | Route quality concerns, scenarios, measures, priorities, and pre-design interactions to `quality-attributes` | MinoDriven quality intent plus formal quality sources | MinoDriven software-quality deck; ISO/IEC 25010 controls taxonomy, not local workflow |
| `DC-CONTEXT` | Route material terminology, role, assumption, scope, and boundary interpretation to `context-interpretation` | MinoDriven context intent plus requirements sources | MinoDriven context verbalization; IREB refines context and boundary mechanics |
| `DC-ORDER` | Resolve material interpretation dependencies before dependent statements; establish Purpose and Goals before Means decisions; establish quality criteria before quality-based comparison | External design reasoning | MinoDriven purpose, context, and quality sources |
| `DC-CAPABILITY` | Confirm installed metadata and report a missing child without simulation | Local runtime safety | Current Skills metadata is the runtime fact |
| `DC-STEP` | Give every Step one child, semantic input and dependency, the child's artifact type and explicit completion declaration, and one state; only the first eligible unfinished Step may be ready or blocked and every other incomplete Step is not-started | User-required contract plus local workflow | Design by Contract supports explicit obligations but does not define this Step schema; evidence restraint is local |
| `DC-RETURN` | Complete a Step only from an actual output reference and the child's explicit completion declaration; do not reassess child semantics in the parent | Local ordered-workflow rule | Composable-Skill guidance is supportive; the lifecycle is local |
| `DC-CATEGORY` | Keep non-foundational coordination in the matching category parent or global router | Local hierarchy ownership | External coherent-unit guidance is supportive only |
| `DC-OUTPUT` | Return a concise semantic route without fixed gate serialization or evaluation records | User-required contract plus external moderation guidance | Agent Skills recommends moderate detail and cutting instructions that do not add value |

Use `references/source-ledger.md` to resolve the named sources and their limits. A map row is traceability, not proof by itself.
