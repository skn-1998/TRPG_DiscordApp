# Source-To-Rule Map

`local architecture` identifies a Skill-family decision, not an externally attributed universal rule.

| Rule ID | Production rule | Basis | Derivation |
|---|---|---|---|
| DP-01 | Run directly on a bounded comparison without a routing parent. | local architecture; O1 | A narrow child should be independently usable and concise. |
| DP-02 | Preserve Actor, Purpose, Context, Constraints, Evidence, horizon, capacity, and candidate uncertainty. | local architecture | These fields define this family's direct contract and the current decision boundary. |
| DP-03 | Express each candidate as an evidence-linked gap from a desired modifiability outcome or obligation. | M1; local architecture | M1 makes changeability the refactoring goal; hypothesis status prevents an inferred target state from becoming fact. |
| DP-04 | Use core or business relevance only when supplied or supported by an identified domain decision. | M2; local architecture | M2 requires business/domain understanding and discussion; code location alone cannot establish competitive value. |
| DP-05 | Compare expected change and current interest against consequence, remediation burden, and constraints. | F1; S1; C1 adoption | These sources support future-touch, impact, evidence, and cost tradeoffs without requiring a universal formula. |
| DP-06 | Treat complexity, size, warnings, coverage, churn, and hotspots as signals rather than priority conclusions. | M3; T1; S1; C1 adoption; local architecture | Static, test, and behavioral signals focus investigation but do not supply purpose or business consequence alone. |
| DP-07 | Do not invent weights, multiply ordinal ratings, or convert a proprietary tool score into business priority. | M3 limit; F1 limit; local architecture; C1 adoption limit | None of the accepted sources publishes a universal weighted ranking model for this Skill. |
| DP-08 | Preserve evidence provenance, scope, time window, counterevidence, and sensitivity when consequential. | S1; local architecture | Multi-source comparison is useful only when unlike measurements and uncertainty are not silently collapsed. |
| DP-09 | Allow ties, deferral, and leave-alone decisions; not all debt merits immediate remediation. | F1; T1; local architecture | F1 and T1 support deferral or leaving debt alone; equal grouping is the local response when evidence does not distinguish candidates. |
| DP-10 | Return `decision-incomplete` rather than fabricate a winner when missing evidence could reverse the choice. | local architecture | Honest uncertainty is part of a usable decision contract. |
| DP-11 | Keep design, legacy-purpose discovery, implementation, tests, and refactor verification in opaque recipients. | local architecture; O1 | Comparison remains independently triggerable only if it does not absorb neighboring methods. |
| DP-12 | Do not impose an owner, reviewer, approval gate, test plan, rollout, release, rollback, branch, commit, review cadence, or prevention program. | local architecture; C1 adoption limit | These activities are not entailed for every bounded comparison and would turn the child into a project workflow. |
| DP-13 | A supported recommendation must expose context, criteria, candidate evidence, rationale, deferred alternatives, and sensitivity. | S1; local architecture | Traceability makes the comparison usable without synthetic precision. |

## Audit Notes

- Source presence does not prove derivation; read each source's limits.
- The comparator's formula and output ledger are not attributed to MinoDriven.
- A recommendation selects an investment target; it does not approve a target design or claim that a refactor is safe.
