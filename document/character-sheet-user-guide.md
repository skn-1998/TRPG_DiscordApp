# キャラクターシート 使い方ガイド

作成: 2026-08-15（実装コミット 2da5c871 時点の実挙動から作成）。
画面名・ボタン名はすべて実物の文言。仕様が変わったらこの doc を先に疑うこと。

## 前提

- Discord アカウントでのログインが必要。`/login` から Discord 認証で入る。
- テンプレート一覧（`/templates`）へは、ログイン後に
  **ヘッダー右上のアバターメニュー →「シートテンプレート」**、または
  **ユーザーページの側ナビ →「シートテンプレート」**から入る。

## 1. テンプレートを作る

1. `/templates` を開く（見出し「シートテンプレート」）。
2. 「新規作成」を押すと draft が作られ、エディタ（`/templates/{id}/edit`）が開く。
3. エディタ上部のメタ入力を埋める:
   - **テンプレート名**・**バージョン**
   - **公開範囲**（非公開 / リンク限定 / 公開）— 後述のとおり **publish には「公開」が必須**
   - **ゲームシステム**（一覧から検索して選ぶ。日本語名・ひらがな・ID のどれでも検索できる。
     例: 「くとぅるふ」で絞り込む。未選択のままだと DiceBot 方言で判定される）・タグ・端数処理
4. セクションとフィールドを組む。フィールドの型:
   - **scalar**: 数値・文字列の単一値
   - **track**: HP/MP/SAN のような現在値/最大値（max・min・style = gauge か checkboxes）
   - **computed**: 式で導出される値
   - **roll**: ダイス記法を持つフィールド
   - **list**: 行の繰り返し

### JSON から作る（貼り付けインポート・2026-08-19 追加）

- 一覧ヘッダーの「**JSON から作成**」を押すとモーダルが開く。テンプレート JSON を貼り付けて
  「作成」を押すと draft が作られ、エディタが開く。
- 受け付ける JSON の形は `document/character-sheet-template-json-spec.md` が正本
  （最小は `{"name": "テンプレート名"}` だけでよい）。
- 画面側で確認するのは「JSON として読めるか・オブジェクトか・name があるか」の 3 点だけ。
  それ以外の構造エラーは**サーバー検証の結果がモーダル内に表示される**。
- API 応答の写し（`templateId` 等が混ざった JSON）を貼ってもよい（余分なキーはサーバーが無視する）。
- 式の短縮参照（`{str}` など）は貼り付け時に `{セクションid.フィールドid}` へ自動補正される。
  補正できない構造のときは補正なしのままサーバー検証に回る（貼り付けが失敗にはならない）。

### AI に JSON を作らせる（生成用プロンプトのコピー・2026-08-20 追加）

- 同じモーダル内の「**生成用プロンプトをコピー**」を押すと、外部 AI 向けの生成プロンプト全文が
  クリップボードに入る。使い方: ① ChatGPT / Claude などのチャットに貼る → ② 続けて作りたい
  ゲーム名やシートの説明を書いて送る → ③ 返ってきた JSON をこのモーダルに貼って「作成」。
- ゲーム名だけの要望でも動く。v1 本文で 9 モデル・計 19 出力（Haiku / Sonnet / Claude 4 Sonnet /
  Claude Opus 5 / GPT 5.6 / Gemini 3.1 Pro / Grok 4.5 / Grok 4.6 / Composer 2.5 Fast）、
  v2 改稿後（2026-08-20）で Haiku/Sonnet 3 出力が、保存時と同じ engine 検証を通ることを実測済み
  （記録: `document/character-sheet-proposals/llm-prompt-trials/`）。
- 「能力値は素値で保存して判定だけ ×5」のような、いあきゃら等と同じ形も要望に書けば作れる
  （例: 「判定ボタンは ×5（1d100<=値*5）」。プロンプト側に記法の説明がある）。
- ただし**ルール数値の正確さはモデルの知識に依存する**。ダイス式や計算式
  （例: 「HP は (CON+SIZ)/10 の切り捨て」）を要望に書くほど正確になる。
  小さいモデルにはルール数値を書いて渡すこと。
- AI の出力に構造エラーがあった場合はサーバー検証エラーがモーダル内に出る。
  そのエラー文を AI に貼り返して修正させるとよい。
- プロンプト本文の正本はコード内定数
  `trpg-next-app/app/features/characterTemplate/templateGenerationPrompt.ts`（変更時は再実測が必要）。

### 保存と検証

- エディタは**自動保存**（入力が止まって約 2 秒後。ヘッダーに「保存中...」→「保存しました。」）。
- 「他所で更新あり。再読み込みして最新の draft を確認してください。」が出たら、
  別タブ等で同じ draft を触っている。「再読み込み」で最新を取り直す。
- 右ペインのタブ「**検証結果**」に publish 検証の警告が出る。
  「**入力プレビュー**」で実際の入力画面を確認できる。

### track の便利機能

- **作成時ロール（rollOnCreate）**: track 詳細パネルに記法（例: `3d6*5`）を入れると、
  キャラクター作成時に自動でロールされ、出目が初期値になる。
  「**試しロール**」ボタンでその場で振って結果を確認できる。
- **リソース操作（±）**: track 詳細パネルで delta（例: `-1`・`+5`）を登録すると、
  Discord のパレットに ± ボタンが生える。delta に 0 は登録できない（publish 検証で拒否）。
- min/max は**助言扱い**。超過した値も保存され、表示が「15 / 10」のように超過を明示する。

### publish（公開）

1. メタ入力の**公開範囲を public にする**（private のままだと publish が 400 で拒否される）。
2. 「publish」を押す。以後この版は**構造変更不可**になる（名前と tags だけ変更可）。
   構造を変えたいときは version を上げて再 publish する。

> 注意: 「公開範囲 = public」は現時点では publish の前提条件としてだけ機能する。
> **自分のテンプレートが他のユーザーに見えるようになる効果はまだ無い**。
> 全員に見えるのは運営配布（下記「配布テンプレート」）だけ。

### 配布テンプレート（旧 CoC）

- `/templates` の一覧には、自分のテンプレートに加えて**「配布」バッジ付きのテンプレート**が
  全ユーザーへ表示される（例: 旧 CoC = クトゥルフ神話 TRPG 6 版）。
- 配布テンプレートは**そのままキャラクター作成に使える**。編集・削除はできない
  （ボタン自体が出ない。API を直接叩いても 403 で拒否される）。
- 投入は運営作業。サーバー側で dry-run 確認のうえ実行する:

  ```bash
  cd TRPG-SERVER && pnpm seed:legacy-coc-template --execute
  ```

  `--execute` を付けないと dry-run（投入内容の表示のみ）。既に同じ templateId＋version が
  あれば skip される（何度実行しても安全）。

## 2. キャラクターを作る

1. `/templates` の一覧で、published になったテンプレート
   （自分のもの、または「配布」バッジ付きのもの）に出る
   「**このテンプレートで作成**」を押す。
2. モーダル「テンプレートからキャラクターを作成」で**キャラクター名**を入れて「作成」。
3. 作成時ロールを持つ track があれば「**作成時の出目**」がその場に表示される
   （例: `DEX: (3D6*5) ＞ 11[2,4,5]*5 ＞ 55`）。「キャラクター一覧へ」で移動。
   出目が無いテンプレートなら、そのままキャラクター一覧へ遷移する。
4. 作ったキャラクターはテンプレートの**その版に固定**される
   （カードの注記どおり「テンプレート更新に自動追従しない」）。

## 3. シートを編集する

1. `/user/character` のカードから「**シート編集**」を開く。
2. シート編集は**自動保存ではない**。「**変更を保存**」で明示保存する。
3. 他の場所で同じシートが更新されていた場合は「**保存競合**」が出る。
   項目ごとに「相手の値を採用 (theirs)」「自分の値を採用 (mine)」を選び、「選択を適用」。
4. 「**公開設定**」でシートの 非公開 / 公開 を切り替えられる
   （公開ページの提供は準備中。設定だけ先に保存される）。

## 4. Discord で使う

前提: キャラクターは Web で作っておく（Discord からは作成できない）。

1. Discord サーバーで **`/create-character-thread`** を実行。
2. 「キャラクターを選択してスレッドを作成...」で自分のキャラクターを選ぶ。
3. スレッドが作られると、**ハブ（シート要約＋操作パレット）が自動投稿**される。
4. パレットの操作:
   - **roll ボタン**（青）: 対応するダイスロールを実行。**スレッド参加者の誰でも押せる**。
   - **± ボタン**（緑/赤）: track のリソース増減（HP−1 など）。**キャラクターの所有者だけ**。
     他人が押すと「❌ この操作はキャラクターの所有者のみ実行できます。」
   - ボタンが多いときは「前へ」「次へ」「グループを選択」で切り替える。

## 5. 現時点の既知の制限

- 全ユーザーに見えるのは**運営配布テンプレート（「配布」バッジ付き）だけ**。
  一般ユーザー同士でテンプレートを共有する機能はまだ無い（public にしても他人には見えない）。
- シートの公開閲覧ページは準備中（公開設定の保存のみ可能）。
- Discord からのキャラクター作成・作成時出目の Discord 表示は無い（Web 側のみ）。
- roll 型フィールドのロール割当（rollable role）はエディタから編集できない。

## 6. 用語集（画面に出る言葉の意味）

エディタの主要ラベルは 2026-08-15 に日本語化された（公開範囲 = 非公開/リンク限定/公開、
上限・下限・式・増減量・ブロック・プール・パーツキーなど）。以下の表の英語は
**内部名（保存データの語彙）・旧表示・検証メッセージに残る用語**の対照として読むこと。
検証エラーの本文と一部の値表示（draft / published など）は今も英語のまま。

### テンプレート一覧

| 画面の言葉 | 意味 |
|---|---|
| draft（ドラフト） | 下書き。自由に編集できる状態。 |
| published（パブリッシュド） | 公開確定した版。**構造は変更できない**（名前とタグのみ変更可）。キャラ作成はこの状態からのみできる。 |
| version（バージョン） | テンプレートの版番号（例: 1.0.0）。publish 後に構造を変えたいときは版を上げて再 publish する。 |
| 新規作成 | 空のテンプレート（draft）を作ってエディタを開く。 |
| このテンプレートで作成 | この published テンプレートからキャラクターを作る。 |
| 配布（バッジ） | 運営が全ユーザーへ配布しているテンプレート。作成には使えるが、編集・削除はできない。 |

### エディタ: テンプレート全体の設定

| 画面の言葉 | 意味 |
|---|---|
| テンプレート名 | テンプレートの表示名。 |
| 公開範囲 | private（非公開）/ unlisted（リンク限定）/ public（公開）。**現時点では publish の前提条件としてだけ機能する**（public でないと publish できない。自分のテンプレートが他人に見える効果はまだ無い。全員に見えるのは運営配布のみ）。 |
| ゲームシステム | ダイス記法の方言を決める設定。一覧から検索して選ぶ（日本語名・ひらがな・ID のどれでも検索可）。保存されるのは BCDice の ID（例: `Cthulhu` = クトゥルフ 6 版・`Cthulhu7th` = 7 版）で、画面には日本語名が出る。未選択なら DiceBot 方言。**一覧に無い ID が既に入っているテンプレートでは「（一覧に無い ID）」と表示され、そのまま保持される**（勝手に消えない）。 |
| tags（タグ） | 検索・整理用の目印。動作には影響しない。 |
| rounding（ラウンディング＝端数処理） | 式の計算結果の端数の扱い。floor = 切り捨て / ceil = 切り上げ / round = 四捨五入。 |

### エディタ: セクションとレイアウト

| 画面の言葉 | 意味 |
|---|---|
| セクション追加 / section id / section label | セクション = フィールドをまとめる大きな区画（例:「能力値」「持ち物」）。id は内部識別子（英数）・label は表示名。 |
| レイアウトプリセット | セクション内の並べ方。stack = 縦一列 / grid = 格子状 / table = 表形式。未選択なら stack。 |
| グリッド列数 | grid のときの列数（2〜4。未選択なら 2）。 |
| 表示幅 | そのフィールドが grid 上で占める列の数（未選択なら 1）。大きい入力欄を横に広げたいときに使う。 |

### エディタ: フィールド共通

| 画面の言葉 | 意味 |
|---|---|
| 型 | フィールドの種類。text = 文字 / number = 数値 / select = 選択式 / checkbox = チェック / computed = 式で自動計算 / roll = ダイスロール / track = 現在値・最大値（HP など）。 |
| id（アイディー） | セクション内での内部識別子（英数）。式から `{セクションid.フィールドid}`（例: `{abilities.str}`）の形で参照される。**後から変えると式の参照が壊れる**ので最初に決める。 |
| フィールド名 / label（ラベル） | 画面に表示される名前（例:「STR」「正気度」）。自由に変えてよい。 |
| description（ディスクリプション） | フィールドの補足説明。入力欄の下に注釈として表示される。 |
| blockId（ブロック ID） | このフィールドを所属させるブロック（後述）の id。 |
| options（オプションズ） | select 型の選択肢の一覧。 |

### エディタ: 数値と式

| 画面の言葉 | 意味 |
|---|---|
| 入力方式 | max などの値を「number = 固定の数値」で入れるか「formula = 式」で入れるかの切り替え。 |
| formula（フォーミュラ＝式） | 計算式。他のフィールドを `{abilities.str}` の形で参照できる（例: `{abilities.con} * 5`）。 |
| max / min（マックス / ミニマム） | 上限 / 下限。**助言扱い**で、超えた値も保存できる（画面に「15 / 10」のように超過が明示されるだけ）。 |
| partsKeys（パーツキーズ） | 1 つの数値を部位ごとに分けて記録するときの部位一覧（例: 装甲を「頭」「胴」…で分ける）。各部位に id（内部名）と label（表示名）を持つ。 |

### エディタ: track（トラック）専用

| 画面の言葉 | 意味 |
|---|---|
| track（トラック） | HP・MP・SAN のような「現在値 / 最大値」を持つフィールド。 |
| style（スタイル） | 見た目。gauge（ゲージ）= 塗りバー / checkboxes（チェックボックス）= マーク列（最大 30 個まで。それ以外は数字表示になる）。 |
| rollOnCreate notation（ロールオンクリエイト記法） | キャラクター**作成時に自動で振る**ダイス記法（例: `3d6*5`）。出目がこの track の初期値になる。 |
| 試しロール | 上の記法をその場で振って結果を確かめるボタン。値は代入されない（結果表示のみ）。 |
| リソース操作（±） | Discord のパレットに増減ボタンを生やす設定。 |
| delta（デルタ＝増減量） | ± ボタン 1 個ぶんの増減量（例: `-1`・`+5`）。複数登録でき、0 は登録できない。全部消すと ± 機能ごと外れる。 |
| resource role へ置き換える | この track に別のロール設定が既に付いているとき、± 用の設定に**上書きする**ことを確認するボタン（元の設定は失われる）。 |

### エディタ: roll（ロール）専用

| 画面の言葉 | 意味 |
|---|---|
| notation（ノーテーション＝記法） | ダイス記法（例: `1d100<={value}`・`2d6+3`）。`{value}` は自分の値を指す。 |
| resultType（リザルトタイプ） | ロール結果の型。number = 数値 / text = 文字 / boolean = 成否 / dice = ダイス結果。 |

### エディタ: blocks / pools（ブロック / プール）

| 画面の言葉 | 意味 |
|---|---|
| blocks（ブロック） | セクション内でフィールドをまとめる小さなグループ。id（内部名）・label（表示名）を持つ。 |
| cap（キャップ） | そのブロックに入る各フィールドの上限の既定値。フィールド個別の「上限」が優先され、無いときだけ cap が使われる。**合計に対する上限ではない**（合計の予算は pools を使う）。超えると**警告表示**される（保存は拒否されない）。 |
| pools（プール） | 複数フィールドの合計を集計して「予算の残り」を見る枠（例: スキルポイントの割り振り）。 |
| total（トータル＝予算） | プールの合計予算。 |
| partsKey / scope（スコープ） | 集計の対象を絞る指定。partsKey = 特定の部位だけ集計・scope = 集計対象のフィールドを限定。「scope を全解除」で絞り込みを消す。 |

### エディタ: ヘッダーと状態表示

| 画面の言葉 | 意味 |
|---|---|
| 保存 / 保存中... / 保存しました。 | draft の保存。自動でも走る（入力が止まって約 2 秒後）。 |
| 検証 | publish できる状態かの検査を実行。結果は右の「検証結果」タブへ。 |
| publish（パブリッシュ） | この draft を公開確定版にする。以後構造は変更不可。 |
| 検証エラー / 検証警告 | エラー = publish できない問題。警告 = publish はできるが注意すべき点。 |
| 保存エラー / 他所で更新あり | 保存に失敗した状態。「他所で更新あり」は別タブ等で同じ draft が更新されたという意味で、「再読み込み」で最新を取り直す。 |
| 入力プレビュー / 検証結果 | 右ペインのタブ。実際の入力画面の見た目 / 検証の結果一覧。 |
| 式評価エラー | プレビューで式が計算できなかったときの表示。 |

### シート画面の表示

| 画面の言葉 | 意味 |
|---|---|
| 15 / 10 のような表示 | 現在値 / 上限。上限を超えていてもそのまま表示される（超過は仕様として許容）。 |
| —（ダッシュ） | 値がまだ確定できないという表示（参照先が未入力・保存値が壊れている等）。 |
| 上限を評価できません | max の式が計算できない状態の警告（参照先の入力を確認する）。 |

### キャラクター関連

| 画面の言葉 | 意味 |
|---|---|
| キャラクター名 / 作成時の出目 | 作成時に付ける名前 / rollOnCreate の結果一覧（この場限りの表示で、後から見返す画面は無い）。 |
| テンプレート更新に自動追従しない | キャラクターは作成時点のテンプレート版に固定される、という注意書き。テンプレートを更新しても既存キャラには影響しない。 |
| 変更を保存 / 保存されていません | シート編集は手動保存。未保存の変更がある状態の表示。 |
| 保存競合 / theirs / mine / 選択を適用 | 他の場所で同じシートが先に保存されていた状態。項目ごとに theirs（ゼアーズ＝相手の値）か mine（マイン＝自分の値）を選んで「選択を適用」で解決する。 |
| シートの公開設定（非公開 / 公開） | シートを公開するかの設定。公開ページ自体は準備中で、設定の保存だけできる。 |
| Discord サーバーに追加 / サーバーを選択してください | このキャラクターを使う Discord サーバーを紐付ける操作。 |
| Discord hub の更新に失敗しています | Discord 側のハブ（後述）への反映が失敗している警告。 |

### Discord 側

| 画面の言葉 | 意味 |
